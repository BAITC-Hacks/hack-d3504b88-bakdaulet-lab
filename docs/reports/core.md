## Подтверждённые проблемы и исправления

Перед изменением реализации исходные 22 теста прошли. Затем новые проверки на исходном коде дали 28 упавших и 28 прошедших тестов (core-cart, openai-core, chat). Это число проверок, а не независимых ошибок.

1. Повтор `confirm` возвращал историческую корзину из `proposals.result`, даже после удаления позиции; также пропускал проверку версии подтверждённого предложения. Теперь повтор возвращает текущую корзину без повторной мутации, версия проверяется до обработки повтора.
2. Предложение могло истечь во время `freshProduct`, но всё равно подтверждалось. Срок теперь повторно проверяется внутри транзакции непосредственно перед записью; момент `expiresAt` уже считается истечением. Воспроизведение детерминировано управляемым Promise и `Date.now`, без ожидания десяти минут.
3. Новые `offers` обходили проверку при confirm/update; update также не сравнивал артикул. Теперь оба действия сравнивают ID, название, артикул, цену и отсутствие вариантов. Подмена ID проверена mock-ответом как дополнительная защита: реальный `ekt.getProduct` уже проверяет соответствие ID.
4. Общий остаток, город и конкретный склад одного товара могли использоваться повторно через разные ключи строк. Добавлена проверка всего количества товара в существующей корзине и предложении, общего лимита и пересечения наборов известных складов. Она работает в prepare, confirm и update. Детали одного товара читаются один раз за операцию.
5. Положительные ID товара/склада теперь проверяются непосредственно в адаптере до обращения к каталогу; проверяется также безопасная целочисленная сумма повторяющихся строк. HTTP-схемы уже проверяли положительные ID — обход HTTP-валидации не заявляется.
6. AI мог вернуть произвольное `output_text` без результатов инструментов, включая выдуманные цену, остаток, сертификат и успешную покупку. Теперь такой ответ заменяется просьбой уточнить запрос. При наличии результатов используются серверные факты, как и прежде.
7. Серверная проверка аргументов AI была неполной: допускала отрицательные ID, лишние поля, пустые/слишком длинные строки. Добавлены строгие Zod-схемы всех семи инструментов; неизвестные инструменты и некорректный JSON возвращают ошибку инструменту до выполнения действия. Инструмента мутации корзины у LLM нет.

Ограничение проверки остатков: существующая схема не хранит распределение общих/городских строк по складам. Поэтому разные пересекающиеся области выбора отклоняются даже при потенциально достаточном остатке. Пользователь должен оставить одну область выбора либо непересекающиеся конкретные склады. Автоматического распределения и миграции БД нет. Непересекающиеся склады разрешены в пределах общего остатка. Это проверка корзины прототипа, не резервирование товара в EKT.
