## Подтверждённые проблемы и исправления

1. Исходный regex превращал `DEMO-AV16 20 А` и `20A` в количество 20, брал первую позицию из склеенной строки, терял артикул без количества, обрезал дроби. Теперь сопоставляется вся строка; сомнительная строка остаётся видимой без выдуманного количества. Ноль, отрицательные числа и дроби сохраняются для исправления и не допускаются к штучному предложению.
2. Точное совпадение артикула повышало confidence всей строки. Теперь confidence остаётся low; количество и единица требуют проверки независимо от найденного товара.
3. Переставленные Excel-колонки и заголовки читались как товарные строки. Добавлены распространённые русские/английские заголовки, десятичная запятая, сохранение номера строки. Неоднозначные/дублирующиеся колонки дают видимые строки для ручного заполнения. Простой формат без заголовков «артикул, количество, единица» сохранён.
4. `pdf-parse.result.text` включает служебные номера страниц даже у сканов: существующий код не вызывал OCR для пустого текстового слоя. Теперь проверяется текст самих страниц; если есть пустая страница, весь ограниченный PDF проходит OCR. Текстовые PDF сохраняют номер страницы.
5. OCR возвращал неструктурированный текст с бюджетом 500 токенов без проверки завершённости. Теперь используется strict JSON schema, проверка Zod и `status=completed`, отдельные nullable поля и признак неясности. Нечитаемый артикул не сопоставляется по догадке. Пустой, некорректный и обрезанный ответ — явная ошибка. Настроены high detail, timeout 60 секунд, maxRetries=0, store=false; инструменты изменения корзины не передаются.
6. Строки свыше 100 и листы свыше 5 терялись молча. Теперь превышение отклоняет документ целиком с просьбой разделить его; PDF ограничен 10 страницами. Сокращённый исходный текст строки имеет явную отметку.
7. Проверка двух байтов `PK` позволяла XLSX-парсеру принять обычный текст за таблицу. Проверяется четырёхбайтовая ZIP-сигнатура; ошибки повреждённых документов понятны пользователю. Добавлены проверка MIME и конечный предел размера даже при некорректном `UPLOAD_MAX_MB`.
8. UploadReview автоматически выбирал все valid-строки, допускал отсутствующую единицу и терял отфильтрованные позиции без сводки. Теперь каждая строка требует отметки «Проверено», неизвестная/отсутствующая единица блокирует выбор, видны причины исключения и полный выбранный состав. Изменение значения снимает отметку. Новая загрузка сбрасывает старый черновик, включая повтор того же файла (отдельно воспроизведено браузерным тестом). Подготовка и подтверждение добавления остаются разными шагами.

## Что НЕ проверено и почему

- **Реальное фото клиента не проверено**: пользователь не предоставлял такой файл. Синтетический JPEG и PDF через настоящее API не заменяют эту проверку.
- Реальный зашифрованный PDF не предоставлен: ветка пароля покрыта mock-тестом. Повреждённый PDF проверен реальным парсером и HTTP.
- Полнота распознавания сложных многостраничных таблиц, DOCX-таблиц, частичных текстовых слоёв, рукописного текста и плохих фото не гарантируется. В DOCX сохраняется консервативный построчный разбор; строки требуют ручной проверки.
- Метры/упаковки и дробные количества не переводятся в штучное предложение. Старый DOC по-прежнему отклоняется явно.
- Live EKT и реальные остатки не проверялись повторно: текущая задача использовала demo для изоляции и три оплачиваемых OCR-пробы. Реальное добавление/заказ в EKT не выполнялись.
- Модель может ошибаться или не заметить позицию даже при полном JSON. Поэтому отметка проверки требуется у каждой строки; гарантии полноты OCR по одной схеме нет.
