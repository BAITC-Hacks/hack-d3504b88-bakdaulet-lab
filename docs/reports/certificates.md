## Подтверждённые проблемы и исправления

До правок исходные 22 теста прошли. Из первых 32 новых тестов 16 упали: `Да`, `Нет`, пустые строки, числовой ID в строке и произвольный текст превращались в URL на ekt.kz; принимались ссылки с credentials и обратными слешами; дубликаты сохранялись; вложенные файлы и HTML с вложенной разметкой пропускались; `INSERT` и `data-href` давали ложные сертификаты.

Теперь нужны явные HTTPS-ссылки, пути или имена документов. Сохраняются относительные пути, URL без расширения, protocol-relative HTTPS и пути с пробелами/кириллицей. Числа, логические значения, пустые строки, текст без признаков ссылки, query-only/fragment-only ссылки и небезопасные схемы исключены. HTTP по-прежнему не принимается, как и в исходном коде.

Извлечение поддерживает регистр ключей, вложенные VALUE/files/SRC/url, метаданные файлов, HTML-атрибуты и сущности. NAME/ID/preview не используются как адрес файла. HTML-комментарии и script/style исключены. Дубликаты убираются после нормализации URL; сохраняется первый источник. Для вложенных структур `source` содержит точный путь, например `properties.SeRtIfIkAt.VALUE[0].SRC`. Есть ограничение глубины и защита от циклов.

Ссылка означает только наличие ссылки в данных источника. Парсер не устанавливает подлинность, срок действия или применимость документа. Basic Auth остаётся только у фиксированного API EKT; переходы по редиректам запрещены. Документы автоматически не скачиваются.
